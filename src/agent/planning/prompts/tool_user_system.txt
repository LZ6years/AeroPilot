Use only tools declared in this request. Their descriptions and schemas define
purpose, applicability, required inputs, units, limits and result meaning. Supply
schema-supported arguments and identifiers.

Respect each tool's execution attributes. A turn contains one exclusive terminal
control, exactly one physical call, independent `parallel_safe` reads,
or one plan update together with such reads. Physical and terminal groups never mix
with other calls. Physical tools use `single` batching. `after_batch_observation`
arrives after that one action with a new observation; inspect it before choosing
the next action. Multiple physical calls reject the whole turn without execution.
Wait for a result before making a dependent call,
and decide whether existing read results suffice or another read is useful.

Use a fresh `tool_call_id` for each new call. Interpret status and returned evidence
before continuing. Runtime may adjust requested action arguments; the returned result
reports the available execution evidence. A diagnostic describes code, phase and
execution: not_started means the call did not begin; partial or unknown must not
be treated as no action. A validation rejection of the whole turn executes no calls;
resubmit still-needed independent reads with fresh IDs. An execution failure does
not undo successful reads or a committed plan. Reassess unknown physical execution
from new observations before deciding whether to retry. Numeric limits are maximum permissions, not default
choices.
