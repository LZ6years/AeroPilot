# 飞行经验库 V1 实施与离线实验结果

## 实现结果

已实现独立 SQLite 库、版本与来源索引、持久维护队列、单 worker 租约/心跳、独立模型审核、
人工发布/撤回/归档，以及 `skill.flight_experience.search`。插件在默认配置中显式关闭。
没有修改 Core、Runtime 或 Context，没有飞行写入工具、自动复盘钩子或重新执行飞行。

入口及说明：[管理操作](flight_experience_library.md)、
[独立模块](../../plugins/research/flight_experience/README.md)。

SQLite 保存经验与不可变版本、标签、来源索引和引用、审核及替代/冲突关系、任务与尝试记录。
原图留在原文件/审计媒体中。搜索只读连接，按发布状态和用途隔离；后台模型调用不持有写事务。
发布检查来源及基础版本，以事务切换完整结果；失败保留旧发布版本。

当前导入入口仅导入离线实验，全部标为 experiment，不能通过改 scope 发布成 production。
生产来源的采集审批入口不在本轮实现中。正式默认搜索不返回这些实验候选。

### 具体生成内容及人工检查

一份返回提议 `supplement`，继续保留“模糊地标时升高以扩大视野”的建议，并称现有证据充分支持。
但 tags 中各字段返回字符串，而契约要求字符串列表，因此在审核前拒绝，未自动修复类型。
语义上，看到更开阔的结构也不能单独证明地标身份正确；升高的适用条件仍需限定。

另一份返回提议 `unchanged`，称四条旧候选都有充分支持，包括：持续直飞帮助找到远处地标、
忽略低置信度/无效距离的 grounding 输出、最后图像符合碎石和建筑目标。结构校验通过，但独立
审核调用超时，未形成审核结论，也未改变候选状态。

人工查看了原始 obs_0003、obs_0006、obs_0014：后者主要是近处砖墙与左侧有限环境。
这些画面不足以直接支持“地标正确”“整个最终位置正确”的表述。无效深度也不能概括为
所有候选定位信息都不可使用；继续前进和升高仍需要路线、净空与观察条件。此人工评述是交付分析，
不冒充独立审核模型的结论，也没有回写正式知识。

### 执行版本说明

真实模型任务启动时的 `store.py` 与 `maintenance.py` 保存在产物的 `execution_source/`。
运行期间继续完成确定性测试，随后修复维护去重并加强错误分类、来源输入校验和查询索引。
模型进程使用已载入的实现与原提示，本轮没有将后续代码的离线检查伪装成新的 provider 调用。
最终工作树通过上述 95 项验证；模型统计仅对应所保存的那次真实执行。

## 结论与限制

已经验证经验存储、版本、异步更新、人工门槛和可选工具连接；当前模型维护的完成率和内容可靠性
仍不足以支持自动发布。旧候选不因为已经入库就更可靠，正式飞行搜索保持关闭。

第一版采用词汇检索，中文使用相邻双字切分，不保证同义词或跨语言召回；实验中的中文查询没有
匹配英文候选时保持空结果。查询不读取全部原日志，来源变化通过 audit、worker 或发布前校验发现。
历史源文件应保持只读。未引入 embedding、历史 RGB recall，也未验证飞行闭环收益。
