## 暂定标题与全文主线

**FlyAgent: A Unified Agent Framework for Aerial Language Tasks via Execution-Grounded Reasoning**

全文主线：

> 多样化空中任务需要共享的决策机制。受工具型 Agent 的启发，FlyAgent 通过执行驱动的循环组织任务所需的能力，并结合行动预期、实际结果与历史判断持续修订策略。

“统一多样化任务”是研究目标，“Execution-Grounded Loop”是方法核心。跨任务实验验证适用范围，受控实验与行为分析验证机制作用。

论证链：

```text
空中语言任务多样
    ↓
研究如何跨任务复用高层决策机制
    ↓
工具型 Agent 的启发：共享循环，按需组织能力
    ↓
物理执行的困难：调用成功不等于预期效果实现
    ↓
Execution-Grounded Loop：关联预期、实际变化与策略修订
    ↓
跨任务结果 + 受控消融 + 真实执行轨迹
```

“统一”指共享冻结模型与高层执行机制，不要求所有任务使用完全相同的信息、动作尺度或技能指导。不得将基准专用高层策略隐藏在环境适配中。

## 1. Introduction

### 第一段：多样化空中任务与统一交互需求

从自然语言操控无人机的需求出发，介绍短程动作、目标相对操作与长程导航。用户可以要求无人机接近、转向或降落，也可以要求其沿道路、经过地标并到达指定地点。

这些任务在时间跨度、空间推理和能力需求上不同，但对用户而言，它们属于同一个无人机助手应当完成的工作。

引出问题：

> 能否让同一个 Agent 根据语言目标组织不同的感知与行动能力，而无需为每类任务分别设计高层决策流程？

### 第二段：已有方法与跨任务复用问题

按研究重点概括已有方法：

- 直接预测动作的模型；
- 地图、地标和记忆增强的导航方法；
- 多模态模型驱动的分层规划与工具型 Agent。

承认它们在各自任务上的进展，然后指出：已有方法通常围绕特定任务设定设计与评估，共享模型不等于共享完整决策机制。

避免宣称“每项任务都必须使用独立模型”，也不把以上类别写成互斥集合。

### 第三段：工具型 Agent 的启发

以 Codex、Claude Code、TRAE 为简短实例，引出一种工作方式：通过共享的决策循环与可组合工具处理不同目标，具体操作序列根据任务和执行反馈形成。

提炼出的启发是：

> 跨任务能力可以来自共享的推理、工具调用与反馈循环，而不一定需要为每个任务构建独立的决策系统。

产品实例只承担启发作用，不作为方法创新或实验比较对象，也不能据此认定空中任务的统一已经得到证明。

可引用的官方背景资料：

- [Introducing Codex](https://openai.com/index/introducing-codex/)
- [Claude Code: How the agent loop works](https://code.claude.com/docs/en/agent-sdk/agent-loop)
- [TRAE](https://www.trae.ai/)

### 第四段：从数字工具调用到物理飞行的困难

指出直接迁移这种工作方式的不足：

> 飞行接口成功返回，不意味着预期的物理效果已经实现。

动作会同时改变位置、姿态和视觉输入。目标在画面中的变化可能来自真实接近，也可能仅由相机转动造成。Agent 需要理解实际变化，并判断这些变化是否支持此前的策略，而不能只根据工具调用成功或最新画面继续行动。

这一段解释为什么不能仅将飞行动作包装成工具，以及为什么需要执行驱动的决策机制。

### 第五段：核心洞察

不同任务共享一个基本过程：

> 形成行动预期 → 执行 → 观察实际变化 → 重新评估判断 → 调整后续策略。

转向任务需要理解姿态变化，接近任务需要判断目标相对关系，长程导航需要关联局部运动与整体进展。统一机制不需要消除任务差异，而应允许 Agent 选择相关能力，并关联历史判断与执行后果。

历史不只是“看到了什么、做过什么”，还要支持判断“此前的预期是否得到支持，哪些策略需要改变”。反思的价值应体现在后续行为，而不是推理文本长度。

### 第六段：提出 FlyAgent

概述三个相互衔接的设计：

1. 共享的任务与能力组织方式；
2. 执行驱动的决策循环；
3. 保留行动预期、执行结果和策略修订的任务历史。

Agent 接收实际运动、视觉观测与工具返回，结合历史行动预期重新评估策略。不同任务的执行过程通过共享循环中的能力使用与策略修订形成，而非完全由基准专用高层流程预先规定。

训练自由指不进行任务专用参数更新，不意味着基础模型没有经过预训练。

### 第七段：实验与贡献

贡献围绕三点组织：

- **统一框架：** 使用共享模型与高层执行循环处理不同粒度的空中语言任务。
- **核心机制：** 将行动预期、实际结果和策略修订关联起来，支持执行驱动的在线调整。
- **系统验证：** 在短程控制与长程导航中验证适用性，并通过受控实验分析循环机制、历史与能力使用的作用。

最后一条在实验完成后应替换为实际发现，不提前填写提升幅度或成功结论。

先区分任务与方法，避免将数据集本身当作算法比较。围绕以下需求组织：

- 短程、多类型飞行控制；
- 长程指令跟随；
- 目标搜索与交互式导航。

以 UAV-Flow、AerialVLN、TravelUAV、OpenFly 等相关研究说明任务设定差异，再讨论动作预测、空间表示与分层规划等解决路径。正式引用时核对各论文的任务、模型与基准角色。

本节落点：FlyAgent 不提出新的任务定义，而研究在不同任务设定下复用同一高层决策机制。

### 2.2 Foundation-Model and Tool-Using Agents

介绍基础模型通过工具与环境交互的研究脉络，包括 ReAct、技能选择与环境反馈，以及导航中的工具型 Agent。

Codex、Claude Code、TRAE 可简短提及，但学术比较主要围绕相关研究，尤其是 AgenticNav 等接近的具身工具型方法。

本节落点：工具使用与推理—行动循环不是 FlyAgent 的首创；本文关注这种组织方式如何支持多样化空中任务，以及如何将物理执行结果用于后续决策。

### 2.3 Memory, Feedback, and Reflective Navigation

按历史信息的作用组织：

- 地图与地标记忆：理解环境与选择路径；
- 历史观测与进度总结：保持长程任务上下文；
- 执行反馈与反思：修正已有判断。

讨论 LookasideVLN、CityNavAgent、AgenticNav 及反思导航方法时，承认其已有的反馈、记忆或进度推理设计。

本节落点：FlyAgent 重点关联“此前的行动预期—实际执行变化—后续策略修订”，并研究这种关联在共享任务循环中的作用。

## 3. Method

本节回答：同一个 Agent 如何组织不同任务，以及执行结果如何改变后续决策。

### 3.1 Problem Formulation and Overview

定义输入与交互过程：

- 自然语言指令 $I$；
- 当前观测 $o_t$，包括可用视觉与飞行状态；
- 可用能力集合 $\mathcal{C}$；
- 当前任务状态与策略；
- 任务内的执行历史 $H_t$。

Agent 可以获取信息、提交短动作窗口、推进任务或报告阻塞。总体描述为：

$$
u_t = \pi_\theta(I, o_t, H_t, \mathcal{C}),
$$

其中模型参数 $\theta$ 保持冻结。不同任务共享高层策略调用方式，但允许观测接口、能力需求和环境适配不同。

明确统一的边界：共享模型与执行机制，不强制所有任务使用完全相同的感知信息、动作尺度或技能指导。

**Figure 2：整体架构。** 展示任务状态、阶段指导、模型、能力接口、只读取证、物理动作窗口以及执行历史的连接。

### 3.2 Task-Conditioned Capability Organization

说明不同语言任务如何进入共享循环。

**任务组织：** 将指令组织为可执行的语义阶段，维护当前目标与任务进展。

**能力组织：** 根据阶段加载相关指导，并在执行过程中按需调用已有能力。

区分三个层面：

- 技能指导：告诉 Agent 如何考虑某类问题；
- 可调用能力：提供观测证据或产生物理影响；
- 环境适配：转换接口，不承担基准专用高层策略。

当前实现按阶段缓存技能选择，不描述为每轮动态重载技能。能力接口的可扩展性也不等同于已经验证丰富的能力组合。

### 3.3 Execution-Grounded Agent Loop

本节是方法核心，应占最多篇幅。

#### Action Intention and Expected Effect

Agent 提交动作前形成当前策略与动作窗口，明确为什么执行这项动作，以及希望环境或自身状态发生什么变化。

使用简短、显式的决策记录，不依赖或公开隐藏 Chain-of-Thought。

#### Evidence Acquisition and Physical Execution

区分两种交互：

- 只读能力调用：获取信息后继续决策；
- 物理动作窗口：执行后重新获取环境与运动状态。

解释其必要性：获取证据不一定需要移动，而移动后旧证据可能不再适用于当前状态。

#### Outcome-Grounded Strategy Revision

执行后结合以下信息重新评估策略：

- 实际位移与姿态变化；
- 当前视觉和目标关系；
- 工具返回与异常；
- 此前策略及预期效果。

随后决定保持、调整、补充取证或报告阻塞。

核心表达：执行反馈不仅被追加到上下文，还被用于重新审视此前的行动判断。

当前实现由模型完成这种比较，不虚构一个独立的数值偏差计算器或反思评分模块。

### 3.4 Execution and Decision History

解释历史如何支持下一轮决策，而不只是展示日志格式。

```text
行动预期 → 工具与动作执行 → 实际结果 → 策略修订
```

重点说明：

- 当前观测与历史观测如何区分；
- 工具调用如何关联其返回结果；
- 实际运动如何与动作意图区分；
- 修订后的策略如何保留到后续决策。

这是单任务内的在线适应，不是跨任务训练或经验学习。若保留完整任务历史，应如实说明，并在效率与局限中讨论上下文增长。

### 3.5 Execution Constraints and Environment Adaptation

集中交代必要的运行机制，不全部包装成创新：

- 短动作窗口与安全约束；
- 工具错误反馈与非法调用处理；
- 阶段完成条件与停止规则；
- 必要的证据时效检查；
- 坐标、动作与评测接口转换。

`done_when` 在这里作为阶段推进约束，不作为全文核心创新。运行时的结构与时效检查不等于独立验证所有语义事实。

说明评测真值和参考轨迹不进入 Agent 上下文，并披露实际可用的位姿、深度等信息及其来源。

## 4. Experiments

实验围绕三个问题展开：

1. **统一性：** 同一决策机制能否覆盖不同粒度的任务？
2. **机制有效性：** 执行历史与策略修订是否带来收益？
3. **行为与代价：** Agent 是否根据结果改变行动，需要多少成本？

### 4.1 Experimental Setup

采用以下主次安排：

- UAV-Flow：短程、多类型飞行控制，主实验；
- AerialVLN：长程语言导航，主实验；
- TravelUAV：完成后作为补充迁移验证。

各基准使用官方评测协议与指标。正式实验前核对指标名称、计算方式和数据划分，不跨基准直接平均不同指标。

| 共享部分 | 允许变化但必须披露的部分 |
| --- | --- |
| 冻结模型与高层循环 | 环境与动作接口 |
| 核心提示与策略修订机制 | 任务输入与可用观测 |
| 能力选择原则 | 必要的坐标与单位转换 |
| 历史组织方式 | 官方终止与评测协议 |

披露模型版本、输入模态、动作预算、调用预算、随机性设置及超参数选择过程。若测试时变更配置，必须列出，不能继续笼统称为完全相同设置。

**长程导航：** 检查历史与策略修订能否支撑多阶段任务，报告 AerialVLN 对应划分结果。

### 4.3 Controlled Comparisons

设置逐步隔离贡献的基线：

- **Direct Action：** 根据指令和当前观测预测动作。
- **History-Augmented Replanning：** 加入观测与动作历史，持续重规划。
- **Tool-Using Agent：** 具备相同工具与工具返回，但不显式组织行动预期及策略修订记录。
- **FlyAgent：** 完整方法。

受控方法尽量共享模型、观测、工具、安全约束和执行预算，同时报告实际使用成本。无工具基线与工具基线的差异不能全部归因于反思；核心机制比较优先使用能力匹配的工具型基线。

回答：收益是否来自执行驱动的历史与决策组织，而不仅是更大的模型、更多工具或更多调用？

### 4.4 Ablation Studies

优先保留与主张直接相关的消融：

- 去除显式行动预期；
- 去除结构化实际运动与执行结果，保留当前观测；
- 去除历史策略修订记录，保留观测和工具历史；
- 将阶段相关技能加载替换为固定加载；
- 去除动作前的多轮取证，限制为固定感知—行动顺序。

每项明确保留与移除的内容，避免多个模块一起消失而无法解释结果。去除必要协议字段时，应使用专门的实验接口，不能让基线因格式校验失败而表现更差。

### 4.5 Execution-Grounded Behavior Analysis

用真实轨迹回答：Agent 是否识别了行动预期与实际结果的不一致？后续行动是否体现了修订？

分析典型事件：

- 执行动作后进展不足；
- 目标丢失或空间关系不符预期；
- 工具结果为空或调用失败；
- 策略调整后仍失败。

展示完整链条：

```text
此前判断 → 预期效果 → 实际结果 → 策略变化 → 后续结果
```

区分“模型声称反思”与“实际行为改变”。报告事件数量、策略改变比例、后续进展及最终成功情况。统计前固定事件定义、观察窗口与抽样规则，不能只选成功案例。

自然失败分析作为诊断证据，不单独宣称因果鲁棒性。当前不将人工扰动设为必要实验。

### 4.6 Efficiency and Cost

报告：

- 模型调用延迟及其分布；
- 每个动作窗口的决策时间；
- 每任务模型轮数与工具次数；
- 输入输出 token；
- 总运行时间。

分别统计模型、工具和模拟器耗时。讨论多轮取证与长历史的代价，不仅强调成功率。不在缺少测量时使用“实时”或“低延迟”结论。

## 5. Limitations and Discussion

主动说明统一机制的适用边界：

- 统一高层循环不意味着理解所有自然语言任务；
- 基础模型仍可能误读视觉变化或形成错误反思；
- 历史增长带来上下文与延迟成本；
- 能力覆盖限制可处理的任务；
- 仿真中的可用状态信息不等同于真实无人机条件；
- 未验证的搜索、开放意图和交互任务不纳入定量结论。

讨论：哪些任务差异可以交给共享循环处理，哪些仍需要新的感知能力、控制器或环境支持？

“我渴了，寻找卖水地点”等开放意图任务，在没有对应评测前仅作为未来方向或明确标注的演示。

## 6. Conclusion

回到与 Introduction 相同的主张：

> 本文研究通过共享 Agent 决策机制组织多样化空中语言任务。FlyAgent 以 Execution-Grounded Loop 关联行动预期、实际执行结果与历史策略修订，使同一个冻结模型能够根据任务和反馈组织能力与行动。

随后用实际实验结论总结适用范围与收益，不以某个 Benchmark 的最高分作为唯一结尾。若某项机制未得到实验支持，应收缩相应贡献。

### 待验证的论文主张

- 不同任务确实复用同一高层机制，而非依赖隐藏的任务专用策略。

- 策略修订能够改善后续进展，而不只是生成不同文本。
- 共享循环能兼顾任务表现与合理调用成本。
- 当前默认能力覆盖较有限，不能宣称已经验证丰富多插件组合。
